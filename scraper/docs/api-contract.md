# JSON contract v1

The HTTP prefix is `/api/v1`; every envelope and offer has `schemaVersion: 1`.
`GET /openapi.json` is generated by FastAPI. `GET /api/v1/schema/offers` wraps the
serialization JSON Schema under `jsonSchema`. Breaking changes require a new version.

| Endpoint | Response |
| --- | --- |
| GET /health | status, schemaVersion, mode (live or fixture) |
| GET /api/v1/providers | configured merchants, browser support, live readiness, terms-review flag |
| POST /api/v1/scrape | ScrapeResponse |
| GET /api/v1/offers | Array of independent ScrapeResponse envelopes; optional provider, merchant, force_refresh |
| GET /api/v1/schema/offers | schemaVersion, jsonSchema |

Request: `{"provider":"GYFTR","merchant":"SWIGGY","forceRefresh":false}`.
Identifiers are case-insensitive; `SWIGGY MONEY` normalizes to `SWIGGY`. Unknown
fields, including arbitrary URLs, are rejected. No incomplete-offer override is exposed.

## Serialization

Properties are camelCase. Monetary values are JSON **strings with two decimal places**,
e.g. `"500.00"`, so Java can bind them to `BigDecimal` without floating-point rounding.
Discount value is a decimal string (at least two and up to six decimal places for rates). For FLAT/CASHBACK
it denotes INR and cannot contain fractional paise; PERCENTAGE denotes percentage points.
Do not parse these fields through float/double. Internally floats and booleans are rejected
for monetary fields. Monetary values are nonnegative and bounded to 18 decimal digits.

All timestamps carry a timezone and serialize in UTC ISO-8601, e.g. `2026-09-18T16:30:00Z`.
Dates without a time use India local start/end of day. Nulls remain null; empty eligibility
lists mean no eligibility information was extracted, not universal eligibility. Source URL
is required; action URL is optional. Links use HTTPS. `terms` preserves relevant extracted
conditions and `availability` is AVAILABLE/UNAVAILABLE/UNKNOWN.

`externalKey` identifies the offer. `contentHash` identifies its normalized commercial
content and excludes observation timestamps. Neither uses array position or scrape time.
`scrapedAt` is the source-fetch time, including cache hits. `lastVerifiedAt` is populated
only for internally consistent offers, using that observation time.

## Envelope and errors

Envelope fields: requestId (UUID), status (SUCCESS/PARTIAL/FAILED), provider, merchant,
startedAt, completedAt, offers, warnings, errors, metadata. Metadata includes cacheHit,
fetchMethod (HTTP/BROWSER/FIXTURE or null), offersFound, offersExcluded and fixture.
Warnings include code/message and optional externalKey. Errors contain controlled code,
safe message, provider, retryable. No stack traces or raw HTML are returned.

HTTP 200 means a usable SUCCESS/PARTIAL envelope; consumers must still inspect status,
warnings and per-offer verificationStatus. Unsupported provider/merchant is HTTP 400.
Malformed requests are 422 with ApiErrorResponse. Source unavailability, forbidden access,
timeouts, disabled providers and rate limits are 503. Robots metadata never disables a provider.
Parsing/validation/no-offer failures are
502. Unexpected API errors are 500. An empty successful list is never invented.

`INCOMPLETE` rows are excluded. `AMBIGUOUS` rows are review candidates and make status
PARTIAL. Do not import them into an optimizer by default. VERIFIED is internal consistency,
not a commercial guarantee. Reject `metadata.fixture=true` in production ingestion.

The request is synchronous because V1 is a small ingestion service. Calls may take time
due to retry and crawl delays. Run refreshes in background ingestion jobs with bounded
client timeouts and coarse retry scheduling. Never chain this into user search latency.

Representative fixtures and exported OpenAPI live under `tests/fixtures/contracts/`.
Re-export after intentional contract changes and review the diff with the Java client.

The 2026-09-19 update preserves ScrapedOffer and fixture response bytes. OpenAPI adds
provider health fields, the aggregate endpoint and precise error enum values.
`contracts/live_*_example.json` contain genuine verified observations and
`contracts/scraped_offer.schema.json` is the exact serialization schema.
FetchMethod remains BROWSER in the existing API contract; source sidecars explicitly
identify that implementation as PLAYWRIGHT. DEMO/FAILED appear in diagnostics, while
the existing canonical verification enum remains unchanged.
